# Vault Schema — brv-marketing-knowledge

База знаний маркетинговой команды Bravo. Используется Steve (CMO), Hype (Content) и будущими агентами. Также открывается Артёмом в Obsidian.

## Структура

- `raw/` — immutable источники. **Только читаем, не правим.**
  - `product-docs/` — канонические доки продукта и ЦА
  - `interviews/` — транскрипты звонков с тренерами
  - `competitors/` — скриншоты, разборы конкурентов
  - `sources/` — внешние источники (Exa-finds, статьи)
- `wiki/` — наш собранный смысл. **Пишем и обновляем мы (агенты + Артём).**
  - `index.md` — навигация
  - `log.md` — хронолог что произошло
  - `entities/` — конкретные «штуки»: ICP-персоны, конкуренты, фичи, каналы, авторы
  - `concepts/` — абстракции: позиционирование, brand voice, hook-формулы, цель команды (`goals.md`), уроки (`learnings.md`)
  - `campaigns/` — каждая кампания
  - `posts/` — каждый опубликованный пост с метриками (шаблон: `playbooks/post-template.md`)
- `playbooks/` — повторяющиеся процедуры для команды

## 🔒 Hard contracts

Файлы, которые меняются **только с явного согласия Артёма**:
- `wiki/concepts/positioning.md`
- `wiki/concepts/banned-words.md`
- `wiki/concepts/visual-style.md`

Если ты агент — не переписывай их по своей инициативе. Если видишь, что устарели — предложи правку Артёму и меняй только после его согласия.

## Три операции

### 1. Ingest (новый источник)

Новый источник (интервью, статья, конкурентский разбор) — канон процедуры: `playbooks/ingest-source.md`.
Коротко: сохранить в `raw/` без правок → дистиллировать в wiki-страницы → залинковать `[[wikilinks]]` → строка в `wiki/log.md`. Hard contracts напрямую не правятся — гейт в плейбуке.

### 2. Query (поиск знаний при работе)

Когда нужны знания для задачи:
1. Сначала прочитай `wiki/index.md` целиком.
2. Перейди по 3-5 наиболее релевантным wiki-страницам.
3. При необходимости — спустись в `raw/` за деталями.
4. Если синтез получился стоящий — сохрани его как новую wiki-страницу.

### 3. Lint (раз в неделю, Steve)

Раз в неделю Steve линтит vault — процедура и чек-лист: skill `lint-knowledge` (репо Steve). Результат — строка `YYYY-MM-DD lint` в `wiki/log.md`.

## Frontmatter conventions

Каждая wiki-страница начинается с YAML-frontmatter. Минимум:

```yaml
---
type: entity | concept | campaign | post | playbook
status: draft | active | archived
updated: 2026-MM-DD
sources: [raw/product-docs/bravo-product.md]   # если страница опирается на raw — repo-root пути, машиночитаемый провенанс
---
```

`sources:` — список raw-источников, на которые опирается страница (пути от корня репо). Это первичный провенанс: позволяет агенту проследить любую claim к источнику, не перечитывая. Для постов — расширенный frontmatter с метриками (см. `playbooks/post-template.md`).

## Ссылки — два механизма, не путать

Разделение держит чистоту графа знаний **и** скорость навигации агента (он ходит по vault через Read/Grep, не кликами):

- **wiki ↔ wiki** → Obsidian-wikilink `[[page-name]]` (по имени страницы). Держит граф: orphans, hubs, backlinks, graph-view — основной слой навигации.
- **wiki → raw / картинки** → markdown с **путём**: `[label](относительный/путь.md)` в теле + дубль источника в `sources:` frontmatter. Путь с `.md` агент открывает мгновенно, не угадывая расположение.
- **Никогда:** raw через `[[ ]]`; bare `[[basename]]` без пути. Первое засоряет граф знаний узлами-источниками, второе заставляет агента искать файл.

Канон Карпатого: wiki стоит *между* тобой и raw. Граф = связи **скомпилированных смыслов** (wiki-страниц); raw — слой-источник (basis) ПОД ними, не узел графа.

## Что НЕ кладём сюда

- Текущие операционные задачи — это Linear.
- Скиллы и инструкции агентов — это `.claude/skills/` соответствующего агента.
- Личные заметки Артёма не для агентов — отдельный personal vault.
